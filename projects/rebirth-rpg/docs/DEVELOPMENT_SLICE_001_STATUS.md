### Combat
- server-owned AttackIntent
- server-owned SkillIntent
- player cannot submit damage, target list, combo index, or reward amount
- cooldown + short busy-state validation
- three-hit basic combo generated by server state
- one simple weapon skill per current abstract weapon style
- server `GetPartBoundsInBox` melee query
- target dedup per attack
- line-of-sight validation
- Level/Rebirth damage multiplier
- kill claim guard against duplicate reward

### Enemy runtime
- sanitized Studio enemy Model is activated only through project tag + `EnemyId`
- project sets health / move speed / aggro / attack values
- bundled third-party AI is not used
- simple brain-off chase/attack loop
- attack Windup state exists as animation/VFX hook
- target distance is rechecked after windup before damage
- server network ownership attempted for unanchored enemy parts
- respawn loop clones the sanitized approved rig after death

### Rewards / equipment
- XP and Gold awarded only by server
- loot roll only by server
- current first loot route can unlock `weapon_start_b`
- inventory ownership is separate from any future Tool/Model visual
- client equip request is ownership/catalog validated and rate-limited

### Client shell
- internal HUD for Level / XP / Gold / Rebirth / objective
- internal equip button for Weapon B
- desktop/gamepad/touch attack action
- desktop/gamepad/touch skill action
- Rebirth test action
- server state is requested/read; client does not author progression values
